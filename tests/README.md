## Patterns that work
- LLM wrapper: pass `config=llm_config` to `generate()`, use `fake_api` for cache/schema/logging tests, or `install_fake_send(monkeypatch, outcomes)` in the test file (fakes `_send_request` + `_get_client`) so the real tenacity loop runs. `_send_request` itself is tested with `FakeOpenAIClient` (records `chat.completions.create(**kwargs)`).
- Transient errors: `openai.APIConnectionError(request=httpx2.Request("POST", "http://test"))`; status errors need `response=httpx2.Response(code, request=...)`, `body=None`.
- Inspect the cache DB with `contextlib.closing(sqlite3.connect(path))` and `?` placeholders.
- RAG pipeline: patch the embedding seam `rag.embedder._embed_texts` and the name `rag.pipeline.generate` (where it is used); pass `pipeline_config` (a dict, no YAML needed) straight to `get_index` / `answer`. For YAML tests write it with `yaml.safe_dump` to `tmp_path` (it round-trips unchanged).
- Retrieval order is hand-checkable with the vocabulary fake: query "leave" vs `leave_policy#000` = 5 / (sqrt(18) * sqrt(2)) = 5/6; all-filler chunks score 1/sqrt(2) = 0.7071 (ties, so assert only rank 1, never ranks 2-3).
- Embeddings: `llm.client.embed` tests use a fake client object with `embeddings.create(**kwargs)` returning `SimpleNamespace(data=[SimpleNamespace(index=, embedding=)])`.

## Pitfalls found
- `httpx2` is imported in the Step 2 tests only for building openai errors; it comes through `openai==3.31`.
- Config tests loop over `REQUIRED_CONFIG_KEYS`; never hand-copy key names or the endpoint.
- openai v3.31 uses `httpx2`, not `httpx`.
- After retries are exhausted the original `openai` error is re-raised (`reraise=True`), as the spec says.
- Filler chunks tie on score in the tiny corpus; never assert an order among tied chunks.
- `seed=0` is falsy: tests check it is sent, keyed and stored (not treated as None).
- Spec does not name the request kwargs for `seed` / `reasoning_effort`; tests assume the openai SDK names (`seed=`, `reasoning_effort=`) as top-level `create()` kwargs.
- `rag.index` imports `CHUNKER_VERSION` by name, so the version test patches both `rag.chunker.CHUNKER_VERSION` and `rag.index.CHUNKER_VERSION`; `index_key` reads the real `configs/llm.yaml` `base_url` unless `rag.index.load_llm_config` is patched.
- A disk load embeds one warm-up query (`rag.index.WARM_UP_TEXT`); tests that count embedded texts after `_LOADED.clear()` must expect that one extra text.
- Step 4: build tiny JSONL files in `tmp_path` (`write_jsonl` helper) and drive `review()` with `scripted_input([...])`. Each refusal test first runs a control (the same set without the defect is accepted), because pydantic `ValidationError` is a `ValueError` and a bare `pytest.raises(ValueError)` could pass for the wrong reason.
- The review edit flow, as the tests script it: `e`, field name, new value; editing `type` asks one more prompt for source_doc_ids (Enter keeps current).
- Review edits: `source_doc_ids` is typed comma-separated and `-` means none (`[]`). At the follow-up after a `type` edit, Enter keeps the current sources and `-` clears them (lookup -> unanswerable).
- Step 5 `main()` tests: the `main_env` fixture (in the test file) writes a tmp harness YAML whose `system` block names functions in the test module itself (`f"{__name__}:fake_answer"`), saves the 8 queries with `save_test_set`, patches `evalharness.runner.git_info` and `evalharness.runner.load_llm_config` (the names where `main` uses them). Refusal tests assert exit 1 AND no `runs` row.
- `get_model_digest`: patch `urllib.request.urlopen` with a fake returning a `BytesIO` of JSON (it is a context manager, so both `with` and `json.load` work).
- LLM-call counts: insert `llm_calls` rows via `llm.client._connect(llm_config["cache_path"])`; a fake `answer` that inserts one row per call proves only this run's ids are counted.

## Pitfalls found (Step 5)
- `make_run_id` uses 8 random hex chars (widened from 4 after the first test run: 100 ids in one second collided ~7% of the time). The uniqueness test draws 100 ids; P(collision) = 4950 / 2**32, about 1e-6.
- `get_outputs` row key for parsed chunks is not named in the spec; `chunks_of()` in the test file accepts `chunks`, `retrieved_chunks` or `retrieved_chunks_json`.
- `ModelDigestError` and CHECK-violation exception types: CHECK failures are accepted as `sqlite3.IntegrityError` or `ValueError` (spec says only "the CHECK rejects").

## Pitfalls found (Step 7)
- Patch `evalharness.judges.generate` (name where used), `get_model_digest` and `load_llm_config` for `main()`; `llm_calls_max_id` returns 0 when the tmp cache file does not exist, so no cache file is needed.
- `FakeJudgeLLM` finds its script by text in the prompt (decompose: the answer; verify: the first claim). Chunk texts in `judge_run_db` therefore must not equal any claim text, and scripted claims[0] must be unique.
- Chunk scores in `judge_run_db` are rank 1 = 0.4, rank 2 = 0.9 on purpose: a judge that sorts by score would show the order wrong.
- Spec does not name the report dict keys. Tests assume `groups[name]` for `all`, `answerable` and each type with `outputs`, `judged`, `judge_failed`, `not_judged`, `ungrounded` (`rate_summary` dict), `faithfulness` (`mean_summary` dict), `claims`, `labels` (supported/unsupported/contradicted), `zero_claim_answers`; top level `ungrounded_ids`, `judge_failed_ids`.
- Spec says `judge_run` returns an `llm_calls` entry, but the call summary is built in `main` from `llm_calls_summary`; tests assert only `status`, `judged`, `judge_failed`, `not_judged`, `skipped_existing`.
- Whether "not judged" items reset the consecutive-failure streak is not in the spec; abort tests avoid having them between the failures.
- `ClaimList` strips claims in its validator, so the stripping test of `decompose` cannot tell the schema's stripping from `decompose`'s own.
- The cut length of "judge failed: ..." (error text only vs whole string) is not in the spec; the test only checks the long text was shortened and the prefix kept.
